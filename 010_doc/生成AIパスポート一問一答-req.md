# 生成AIパスポート一問一答-仕様書

## 概要

GUGA（生成AI活用普及協会）が主催する「生成AIパスポート試験」の学習を目的とした、GitHub Pagesで公開する静的な一問一答Webアプリケーション。

4択問題に加えて「？」（わからない・要復習）を選択でき、10問・30問・60問の問題数で演習できる。演習中は回答直後に正誤と解説を確認でき、演習終了後は正答率、正解・不正解・「？」の状況、および各問題の解説を確認できる。

> **資格名に関する注意**  
> 「生成AIパスポート」はIPA主催の資格ではなく、GUGA主催の資格である。本プロジェクトではGUGAの生成AIパスポート試験を対象とする。IPAのITパスポート試験に公開されている生成AI関連サンプル問題は、必要に応じて参考資料として別区分で扱う。

## 目的

### 解決すべき課題はなにか

- 生成AIパスポート試験の学習で、短時間に繰り返し問題演習を行いたい。
- 問題を解くだけでなく、なぜ正解・不正解なのかを理解したい。
- 間違えた問題と「？」を選んだ問題を後から見つけ、復習したい。
- 問題の出典・参照元を確認しながら、公式情報と非公式情報を区別して学習したい。

### 何を実現するのか

- ブラウザだけで動作する一問一答形式の学習画面。
- 基礎問題120問に加え、中級〜応用の本番対策問題80問を収録する。
- 10問・30問・60問から演習問題数を選択できる機能（60問は本試験の問題数を想定）。
- 4択の回答と、別枠の「？」（わからない・要復習）を選択できる機能。
- 問題を後から見直し、最終提出前に「？」から通常の回答へ変更できる機能。
- 演習終了後に、正答率、正解数、不正解数、「？」の数を表示する機能。
- 不正解問題と「？」を選択した問題をマークして一覧表示する機能。
- 各問題について、正答、正誤の理由、試験対策として覚える周辺知識、出典リンクを表示する機能。
- GitHubリポジトリへの変更を契機に、GitHub Pagesへ自動デプロイできる構成。

### 今回は何を扱わないのか

- GUGAの本試験問題・過去問を「過去問」と称して転載すること。
- GUGAの本試験における合否判定や公式な得点保証。
- 会員登録、ログイン、サーバーサイドデータベース。
- 個人の学習履歴を外部サーバーへ送信する機能。
- 問題文・解説の自動生成を、公開時のビルド処理や利用者のブラウザ上で行う機能。
- 初期リリースでの管理者向け問題登録画面。

## 用意するもの

- GitHubリポジトリ
- GitHub Pagesを有効化できるGitHubアカウント
- 問題データ（JSONまたはTypeScriptの静的データ）
- 問題・解説・出典をレビューするための公式資料
- Node.js、npm、TypeScript、Vite（開発時）
- GUGA公式の最新シラバス、公式テキスト・公式例題など
- 問題の出典を確認するためのURL一覧

## 前提・用語

### 対象試験

- 対象：GUGA「生成AIパスポート試験」
- 主催：生成AI活用普及協会（GUGA）
- IPAのITパスポート試験とは別資格として扱う。
- 試験制度、シラバス、法令、サービス仕様は変更されるため、問題データには参照日を記録し、定期的に見直す。

### 出典区分

問題データには、次の出典区分を必ず持たせる。

| 区分 | 意味 | 「過去問」と表示できるか |
|---|---|---|
| `official-syllabus` | GUGA公式シラバス・公式資料に基づく問題 | できない |
| `official-example` | GUGAまたはIPAが公式公開する例題・サンプル問題に基づく問題 | 公式例題として表示する |
| `third-party-mock` | 第三者が公開する模擬問題に基づく問題 | 本試験の過去問とは表示しない |
| `original` | シラバス・公式資料から作成したオリジナル問題 | できない |

GUGAは本試験の過去問を公式公開していないため、初期リリースでは「何年の何問目」という情報が存在しない問題が含まれる。出典欄には、実際の試験回・問題番号を推測して記載しない。

第三者問題を参照する場合は、第三者問題の公開年月、問題番号、出典URL、参照日を記録する。ただし、出典元の利用条件が不明な本文転載は行わず、原則としてオリジナルの設問・選択肢・解説を作成する。

## 要件・機能

### 機能要件

#### F-01. スタート画面

- アプリ名と対象試験を表示する。
- 「10問」「30問」「60問」のいずれかを選択できる。
- 問題バンクの登録数が選択数未満の場合、その選択肢は無効化する。
- 演習開始前に、出題範囲と出題順の方針を表示する。
- 初期リリースでは、問題を登録済み問題から重複なしで選ぶ。

#### F-02. 問題表示

- 1画面に1問を表示する。
- 問題文、選択肢A〜D、「？」を表示する。
- 選択肢の文言は、問題データの登録順と表示順を一致させる。
- 現在の問題番号と全問題数を表示する。
- 回答済み・未回答・「？」の状態を確認できる。

#### F-03. 回答・見直し

- A〜Dのいずれか1つ、または「？」を選択できる。
- 回答を選択すると、選択肢を正解は緑、不正解は赤で表示する。誤答時は正解の選択肢も緑で表示する。
- 回答選択後に、正誤の理由、正解、周辺知識の用語と簡単な説明を表示する。
- 「？」は「現時点では回答を確定できない・要復習」を意味する。
- 「？」を選んだ後も、提出前であれば通常の選択肢に変更できる。
- 前後の問題へ移動できる。
- 未回答の問題がある場合、提出前に警告を表示する。
- 「？」を選択した問題は、通常の不正解とは別の状態として保持する。

#### F-04. 結果表示

- 提出後に以下を表示する。
  - 正解数
  - 不正解数
  - 「？」の数
  - 未回答数（通常は提出不可とするが、将来の設定変更に備えて状態を持つ）
  - 正答率
- 正答率は、`正解数 ÷ 出題数 × 100` とする。
- 「？」は正答率の分子に含めず、0点として扱う。
- 正答率は小数第1位まで表示し、分母は出題数とする。
- 本アプリの正答率は学習用の指標であり、公式試験の合格判定ではない。

#### F-05. 問題別レビュー

- 結果画面から、全問題の回答状況を一覧で確認できる。
- 不正解問題には「不正解」マークを付ける。
- 「？」を選択した問題には「要復習」マークを付ける。
- 「？」かつ正解扱いになる状態は作らない。
- 各問題について、次の内容を表示する。
  - 問題文
  - 利用者の回答
  - 正解
  - 正誤の理由
  - 試験対策として覚えるべき周辺知識
  - 出典区分
  - 参照年月・問題番号（存在する場合）
  - 出典元へのリンク
- 出典リンクは新しいタブで開く。

#### F-06. 学習状態の保存

- 演習中の状態は、ページを再読み込みしても復元できるようにする。
- 保存先はブラウザの`localStorage`とし、外部送信しない。
- 「最初からやり直す」操作で、現在の演習状態を削除できる。
- 保存データの形式にはバージョン番号を持たせる。
- 問題データの更新で復元できない場合は、状態を黙って破棄せず、利用者に再開できない理由と再スタート方法を表示する。

#### F-07. 問題データ管理

1問につき、最低限次の項目を持つ。

```ts
type Question = {
  id: string;
  category: string;
  question: string;
  choices: [string, string, string, string];
  answerIndex: 0 | 1 | 2 | 3;
  explanation: string;
  relatedKnowledge: string[];
  source: {
    type: "official-syllabus" | "official-example" | "third-party-mock" | "original";
    title: string;
    publishedAt?: string;
    questionNumber?: string;
    url: string;
    accessedAt: string;
  };
  syllabusVersion?: string;
  reviewedAt: string;
};
```

- 「？」は問題データの5番目の正答選択肢ではなく、利用者の回答状態として扱う。
- 1問につき正解は1つとする。
- 問題文、選択肢、解説、周辺知識、出典URLを公開前にレビューする。
- URLが無効になった場合、問題を削除するのではなく、リンク切れとして検出できる仕組みを用意する。

#### F-08. 問題の出題方針

- 初期リリースの問題バンクは60問以上とし、60問モードを利用可能にする。
- 1回の演習では同一問題を重複出題しない。
- 初期リリースでは、カテゴリが偏りすぎないようにカテゴリ別の出題数を調整する。
- 出題順は初期リリースではランダムとする。
- 出題元と正答の位置も偏りが出ないようにレビューする。
- シラバス改訂時は、問題にシラバスバージョンを付け、旧問題を継続利用するかを判断する。

#### F-09. 問題一覧

- トップ画面および結果画面から問題一覧画面へ移動できる。
- 問題をカテゴリ別にまとめて表示する。
- 各問題の問題ID、カテゴリ、問題文を確認できる。
- 問題をクリックまたは展開すると、正解、正誤の理由、周辺知識、出典リンクを表示する。
- 問題一覧は演習の回答状態や保存状態を変更しない。

### UI/UX要件

- スマートフォン、タブレット、PCで利用できるレスポンシブレイアウトにする。
- 選択状態、正解、不正解、「？」を色だけに依存せず、文字・アイコン・枠線でも表現する。
- キーボード操作だけで、選択肢、前後移動、提出を操作できる。
- スクリーンリーダーで問題番号、選択状態、結果マークを理解できるラベルを付ける。
- 回答前は正解を表示せず、回答後は正誤・正解・正誤の理由・周辺知識を表示する。
- 誤操作による演習終了を防ぐため、提出・リセットには確認を設ける。
- 外部リンクで移動する前に、出典元サイトへ移動することを示す。

### 非機能要件

- 静的ファイルのみで動作し、バックエンドを必要としない。
- GitHub Pagesのサブパス配下でも動作する相対パス構成にする。
- 初回表示を軽くするため、問題データを必要以上に分割・重複させない。
- JavaScript無効時は、利用できないことを説明する最低限のメッセージを表示する。
- 問題データに個人情報、APIキー、秘密情報を含めない。
- 主要ブラウザの現行版を対象とする。
- 生成AIサービスのAPIを本番動作に使用しない。問題・解説は公開前に人間が確認した静的データとする。

### コンテンツ・著作権要件

- GUGAの本試験過去問が非公開であることを、アプリ内の注意書きとドキュメントに明記する。
- 「過去問」「本試験問題」と誤認させる表現を使用しない。
- 参照元の文章をそのまま転載せず、シラバスの学習項目に基づくオリジナル問題として作成する。
- 第三者資料を参照した場合は、参照元、公開年月、問題番号（ある場合）、URL、参照日を表示する。
- 利用条件が確認できない第三者資料の本文・画像・解説は取り込まない。
- 法令、サービス仕様、ガイドラインなど更新される情報は、参照日と対象バージョンを表示する。

## 画面構成

1. **トップ画面**
   - アプリ名
   - 対象資格・注意事項
   - 問題数選択（10問 / 30問 / 60問）
   - 問題一覧へのリンク
   - 学習開始
2. **演習画面**
   - 進捗表示
   - 問題文
   - A〜Dの選択肢
   - 「？」ボタン
   - 前の問題 / 次の問題
   - 回答状況一覧
   - 提出
3. **問題一覧画面**
   - カテゴリ別の問題一覧
   - 問題ID、カテゴリ、問題文
   - 展開式の正解・解説・周辺知識・出典
4. **結果画面**
   - 正答率
   - 正解数 / 不正解数 / 「？」数
   - 問題別の状態一覧
   - 要復習問題への絞り込み
   - 解説表示
   - もう一度挑戦
4. **出典・使い方画面**
   - 本アプリの位置付け
   - 出典区分の説明
   - GUGA公式ページ、公式シラバスへのリンク
   - 問題作成・更新方針

## システム構成図

```text
利用者のブラウザ
    │
    ├─ 静的HTML / CSS / JavaScript
    ├─ 静的問題データ（JSONまたはTypeScript）
    └─ localStorage（演習中データのみ）
    │
    ▼
GitHub Pages
    ▲
    │ GitHub Actions
    │ build / test / deploy
    │
GitHubリポジトリ
    ├─ src/
    ├─ public/questions/
    └─ .github/workflows/deploy-pages.yml
```

## 技術方針

- フロントエンド：TypeScript + Vite
- UI：初期リリースはフレームワークを使わないか、依存を最小限にした構成とする
- 問題データ：型定義付きJSONまたはTypeScriptの静的データ
- 永続化：`localStorage`
- ホスティング：GitHub Pages
- CI/CD：GitHub Actionsで、プッシュ時にビルド・テスト・デプロイ
- テスト：問題データ検証、正答率計算、回答状態遷移、主要画面のブラウザテスト

## GitHub Pages公開要件

- `main`ブランチへの変更を公開トリガーとする。
- GitHub Actionsでビルドとテストが成功した場合のみデプロイする。
- GitHub Pagesの設定はGitHub Actions方式を使用する。
- リポジトリ名に依存しない相対パスを使用する。
- `404.html`などGitHub Pages上で必要な静的ファイルを用意する。
- 公開URLはリポジトリ確定後に設定し、READMEまたはマニュアルからリンクする。
- 問題データだけを変更した場合も、同じ検証・デプロイ経路を通す。

## 問題・解説の作成ルール

1. 最新のGUGA公式シラバスから学習項目を選ぶ。
2. 公式資料、公式例題、または利用条件を確認した第三者模擬問題を参照する。
3. 本試験過去問と誤認されないオリジナルの問題文・選択肢を作成する。
4. 正解が1つだけになることを確認する。
5. 正誤の理由を、他の選択肢が不適切な理由も含めて記載する。
6. 周辺知識として、関連用語、リスク、対策、法令・ガイドライン、実務上の注意点を記載する。
7. 出典区分、出典URL、参照日、シラバスバージョンを記録する。
8. 公開前に内容の正確性、リンク、著作権、更新日をレビューする。
